# Сервис учета отпусков

## Назначение
Проект автоматизирует процесс планирования и учёта отпусков внутри компании. Позволяет сотрудникам подавать заявки на отпуск, руководителям — согласовывать их, а HR‑отделу — вести единый календарь отпусков и следить за остатками дней.

## Целевая аудитория
Продукт рассчитан на организации, заинтересованные в автоматизации учёта отпусков:
Малый и средний бизнес — компании без выделенного HR‑отдела, которым нужен простой инструмент учёта отпусков.
Крупные компании и корпорации — организации с многочисленным персоналом и развитой кадровой службой.
HR‑отделы / HR‑директора — команды, отвечающие за планирование, учёт и контроль кадровых ресурсов.
IT‑департаменты компаний — как заказчики внедрения и администрирования решения.
Аутсорсинговые HR‑агентства и кадровые сервисы — компании, ведущие учёт отпусков для нескольких клиентов.

## Предметная область
Предметная область — кадровый учёт и управление персоналом. Система хранит типы отпусков и заявки сотрудников на отпуск: ежегодный оплачиваемый, неоплачиваемый, по уходу за ребёнком и по болезни. Для заявок на ежегодный оплачиваемый отпуск учитывается остаток дней; остальные типы его не уменьшают. Система также проверяет пересечение дат, позволяет отменять заявки и восстанавливает баланс дней при отмене оплачиваемого отпуска.

## Основные сущности

### User — пользователь системы

Объект `User` представляет сотрудника, для которого ведётся учёт отпусков.

**Атрибуты:**
- `id` — уникальный идентификатор пользователя;
- `name` — ФИО сотрудника;
- `vacation_days_available` — количество доступных дней отпуска;
- `vacation_days_total` — общее количество дней отпуска за год.

**Методы:**
- `reduce_days(duration)` — списать дни отпуска; возвращает `False`,
  если дней недостаточно;
- `restore_days(duration)` — вернуть дни при отмене заявки;
- `from_data(data)` — `@classmethod`, создать объект `User` из данных JSON;
- `to_dict()` — преобразовать объект в словарь для сохранения в JSON;
- `__str__()` — строковое представление пользователя.

### Vacation — тип отпуска

Объект `Vacation` описывает категорию отпуска.

**Атрибуты:**
- `id` — идентификатор типа;
- `name` — название типа;
- `deducts_vacation_days` — признак, что заявка этого типа расходует доступные дни оплачиваемого отпуска.

В справочнике заданы ежегодный оплачиваемый, неоплачиваемый отпуск, отпуск по уходу за ребёнком и отпуск по болезни.

### VacationRequest — заявка на отпуск

Объект `VacationRequest` представляет заявку на отпуск, поданную пользователем.

**Атрибуты:**
- `id` — уникальный идентификатор заявки;
- `user` — объект `User`, которому принадлежит заявка;
- `vacation` — объект `Vacation`, задающий тип отпуска;
- `start_date` — дата начала отпуска (`YYYY-MM-DD`);
- `end_date` — дата окончания отпуска (`YYYY-MM-DD`);
- `duration` — длительность отпуска в днях;
- `status` — состояние заявки: `pending`, `approved`, `cancelled`.

**Методы:**
- `cancel()` — отменить заявку и вернуть дни пользователю через
  `user.restore_days()`, если тип отпуска расходует баланс;
- `from_data(data, users)` — `@classmethod`, создать объект `VacationRequest`
  из JSON и восстановить связи с `User` и типом отпуска;
- `to_dict()` — преобразовать объект в словарь для сохранения в JSON;
- `__str__()` — строковое представление заявки.

## Основные функции (реализованные на ПР1)
- `create_user(name, days_available = 28)` - функция регистрации пользователя в системе
- `reduce_vacation_days_available(vacation_duration)` - функция уменьшение количества дней, доступных для отпуска, после создания заявки на отпуск
- `create_vacation_request(...)` — функция создания заявки на отпуск с выбранным типом
- `check_application_status()` - функция проверки статуса заявки
